01 · The model

What Managed Deep Agents actually is.

Two layers: a harness that runs the agent loop, and a managed runtime that hosts it, so there is nothing to provision and nothing to keep alive.

The Deep Agents harness handles the loop itself: planning, tool calls, the agent's filesystem, and delegation out to subagents. The managed runtime is LangSmith's Agent Server, which hosts that agent, keeps sessions alive across restarts, and supplies the sandboxes and the scheduler.

LangChain's own framing is the useful one. You focus on what your agent does, and the platform runs it. There are no servers to run and no infrastructure to wire together. Everything you would normally spend the first two weeks building, session persistence, a code sandbox, a cron runner, a memory store, an auth layer, a Slack front door, arrives as configuration.

02 · The blocks

Every block, and what it replaces.

This is the diagram from the Reel, written out. Each capability is a file or a directory in the project, which is why a coding agent can assemble it for you.

Read this table as a checklist of decisions you no longer have to make. The left column is what you write. The right column is the thing you would otherwise have built yourself, badly, on a deadline.

You writeIt gives you
agent.pyThe agent definition: model choice and core settings
instructions.mdThe system prompt that defines how the agent behaves
skills/Task-specific playbooks the agent pulls in when relevant
tools/Custom functions and integrations with external services
connectors/MCP connectors: remote servers that hand the agent more tools
middleware/Your own logic wrapped around model and tool calls
sandbox/An isolated filesystem and shell so the agent can run code safely
memory.pyDurable preferences and knowledge that survive the session
identity.pyMulti-user support: private threads and per-user credentials
channels/Messaging front doors, Slack being the obvious one
schedules/Managed cron, so the agent starts itself on a timetable
evals/Tests, so you know whether a change made it better or worse
The two that change how a project feels are schedules and channels. A scheduled agent stops being something you visit and becomes something that arrives. A channel means the people who need it never have to learn your interface.
03 · The quickstart

Ship one in about ten minutes.

This is LangChain's quickstart, condensed to the commands, so you can see how short the distance is before you commit an afternoon to it.

Install the CLI and scaffold a project:

uv tool install managed-deepagents mda init research-assistant cd research-assistant

Put two keys in .env: your model provider key and your LangSmith key. Then edit instructions.md, which is the system prompt, and point agent.py at the model you want:

from managed_deepagents import define_deep_agent agent = define_deep_agent( name="research-assistant", model="openai:gpt-5.5", tools=[{"type": "web_search"}], )

Run it locally, then deploy it. The deployment URL prints when it finishes:

uv sync mda dev . mda deploy .

04 · The tutorial

Tool, memory, schedule: the part that matters.

The quickstart gives you a deployed agent. This tutorial gives you one that remembers what it learned and shows up on its own on a weekday morning.

It picks up the quickstart project and does four things in order. It swaps the built-in provider search for a Tavily tool you author yourself, so you control the API and its parameters. It extends the instructions to say what is worth remembering. It adds a memory declaration at the project root so that knowledge persists across conversations and across deployments. Then it schedules a cron job that runs the agent at 8am Pacific on weekdays to summarise what it knows and flag the open questions.

Do this one with your own domain in place of research. The daily digest pattern, an agent that wakes up, reads what it has accumulated, and tells you what it still does not know, is the single most useful shape in the whole platform.

07 · The instruction

Tell your coding agent to use it.

This is the thing from the Reel. Left alone, Claude or Codex will invent an architecture for you, and it will be worse than this one. Paste this at the top of the session instead.

We are building an agent on LangChain's Managed Deep Agents (MDA), not from scratch.

Before you write anything, read these:
- https://docs.langchain.com/langsmith/python/managed-deep-agents-overview
- https://docs.langchain.com/langsmith/python/managed-deep-agents-quickstart
- https://docs.langchain.com/langsmith/python/managed-deep-agents-tutorial

Rules:
1. Do not hand-roll an agent loop, a session store, a scheduler, a code
   sandbox, a memory layer, an auth layer, or a Slack integration. MDA
   provides all of these. Use them.
2. Scaffold with `uv tool install managed-deepagents` and `mda init `.
   Work inside that project structure.
3. Put behaviour in instructions.md and skills/, not in Python control flow.
4. Custom capability goes in tools/ or connectors/ (MCP). Cross-cutting
   logic goes in middleware/.
5. Anything worth remembering between runs goes in memory.py, not in a
   file you invented.
6. If it should run without me, add it to schedules/. If a human needs to
   talk to it, add a channel.
7. Run locally with `mda dev .` and deploy with `mda deploy .`.

Here is what the agent needs to do:
[describe the job, the inputs, the outputs, and who it is for]

Start by telling me which MDA blocks this job needs and which it does not,
and wait for me to confirm before you generate any code.
The last line is the part people delete, and it is the part that saves you. A coding agent that lists the blocks first will catch a wrong assumption in one sentence rather than in four hundred lines.
08 · What to do now

Pick one. Use it today.

Reading the docs is not the outcome. A deployed agent that runs itself on Monday morning is the outcome.

  • If you have never built an agent: start at 05, watch the explainer, then run the quickstart in 03 exactly as written. Change nothing on the first pass.
  • If you already have an agent held together with cron jobs and glue: start at 02, find the blocks you have hand-built, and port those first. Schedules and memory are usually the fastest wins.
  • If you build with Claude or Codex: go straight to 07, paste the instruction, and describe the job. Let it tell you which blocks it needs before it writes anything.
  • If you have twenty minutes and no laptop: 05, at 1.5x. It is the highest ratio of understanding to time on this page.
