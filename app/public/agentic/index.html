01 · The repo

mattpocock/skills. Skills for real engineers.

A skill is a file that tells your coding agent how to do a job. Matt Pocock published the ones he uses every day, and they enforce a process instead of hoping for one.

The repo is MIT licensed and works with Claude Code, Codex and the other agentic coding tools. It was number one trending on GitHub when I filmed the Reel. Matt built it, maintains it and documents it. I just use it.

02 · Install

Two commands, then one setup run.

In Claude Code the repo installs as a plugin. In Codex or any other agent it installs as editable files. Either way you run the setup skill once per repository.

Claude Code, from your terminal:

claude plugins install mattpocock-skills

Or inside a Claude Code session:

/plugin install mattpocock-skills

Codex and other agents, or if you want to edit the skill files yourself:

npx skills@latest add mattpocock/skills

Then, once in each repo you work in:

/setup-matt-pocock-skills
These commands are copied from the repo README. If they change, the README wins, so check it if something does not run.

04 · The five steps

Each step in the video is one skill.

This is the map from what I said on screen to what you type. Every link goes to Matt's page for that skill, so you read the rules from the author, not from me.

1

Grill me /grill-me or /grill-with-docs

The agent interviews you, one question at a time, until the plan has no soft spots. Use grill-with-docs when you want the terms and decisions written into the repo as you go instead of left in the chat.

The /grill-me skill →    The /grill-with-docs skill →
2

Specs /to-spec

Turns the conversation you just had into a written spec you can read in plain English. No new interview, it compresses what was already decided.

The /to-spec skill →
3

Tickets /to-tickets

Breaks the spec into small tickets with technical instructions an agent can implement, each one declaring which tickets block it.

The /to-tickets skill →
4

Build /implement

Takes a ticket or spec and turns it into a commit. Test first at the agreed seams, typecheck, review, commit. A fresh context window per ticket is the point.

The /implement skill →
5

Review /code-review

Judges the diff on two separate axes, each in its own sub-agent: does it follow the repo's standards, and does it match the spec.

The /code-review skill →
From there you stay in control through the spec. If you need to change something, change the spec and run the flow again. Don't edit the code underneath it blind.

06 · What to do now

Pick one. Use it today.

Reading about the flow does nothing. Running it once on a real, small feature teaches you more than the whole reading list.

  • If you are non technical: install it, then type /grill-me and describe the thing you want built. Answer every question. Stop there for today and read the spec it produces.
  • If you already use Claude Code or Codex daily: run the full flow on one ticket-sized feature: grill, to-spec, to-tickets, implement, code-review. Watch Matt's video first.
  • If you keep going in circles on a broken project: stop patching. Run /grill-with-docs on what the project is meant to do, get a spec, and rebuild from the spec.

See what's possible. Then build it.
