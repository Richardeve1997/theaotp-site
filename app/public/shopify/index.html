01The setup guide

The setup guide, in four steps.

A chief of staff agent runs a council on one decision, then hands you the answer to read or listen to.

This is the setup Tobi Lütke, the CEO of Shopify, described on The Knowledge Project. First what he does, then my version of it, step by step. The folder, the prompt and the limits are my suggestions, not his.

What Tobi does

  • His AI chief of staff has all his notes and access to a lot of company systems.
  • For a really important decision it builds a council of five or six experts: a data role, a paper-research role, the business view and maybe the engineering view.
  • It runs the council across several models. He named Grok, ChatGPT, Opus and maybe Kimi, and said that list "changes all the time".
  • A randomly chosen model writes the synthesis.
  • The result comes back as an audio message. He queues it up and listens in the gym in the morning.
His numbers: about 15 to 20 dollars in tokens and half an hour, for work he says would otherwise take a month. He is also clear about what the council is for: "creating the right environment for judgment". Machines can't take responsibility, so the call stays with him.

Your version

  • 1Make a folder and write one page of context.Create council/context.md. Put in who you are, the decision, what you have already tried, your limits and the numbers that matter. Keep it to one page, because every agent in the council reads it and you pay for it each time. Each model you add is another company that sees it, so leave out anything you would not send them.
  • 2Paste the prompt into your agent.Use Claude Code, Codex or any agent that can read files, run a command and call more than one model. Fill the three brackets. Keep your API key in an environment variable, never in the prompt.
You are my chief of staff. Run an AI council on the decision at the bottom.

Context: read council/context.md. It is everything the council may know about me and this decision.
Models: [3 OR 4 MODEL NAMES FROM DIFFERENT LABS, EXACTLY AS YOUR PROVIDER LISTS THEM]
Access: [HOW YOU CALL THEM, FOR EXAMPLE "OpenRouter, key in the OPENROUTER_API_KEY variable"]

1. Pick four roles that will disagree usefully. Always include a data role and a paper-research role. Add the business view, and one more that fits the decision.
2. Give each role one model from the list. Run each role on its own, with no sight of the other answers.
3. Each role answers in 300 words or fewer: its position, its best evidence, and what would change its mind. Save each answer in council/runs/.
4. Choose the summariser with a real random pick, not your own judgment. Run this with the model names from the list and use the result: python3 -c "import random; print(random.choice(['MODEL_A','MODEL_B','MODEL_C']))"
5. Send every answer to that model. It writes council/brief.md, one page: the recommendation, the strongest disagreement, any bias it can see in the answers, and what would change the call.
6. Write council/audio.txt: the brief as plain spoken sentences, no lists or markdown, under 700 words.
7. Finish with the tokens and cost of every call. Do not make the decision for me.

Decision: [WRITE THE DECISION HERE]

How to give the agent several models is in section 02.

  • 3Read the brief.The agent saves council/brief.md: one page with the recommendation, the strongest disagreement, any bias the summariser sees in the answers and what would change the call. The last line of the prompt tells the agent not to make the call, so that part is yours.
  • 4Listen to it.The prompt also writes council/audio.txt, the brief as plain spoken sentences. On a Mac, the built-in say command turns it into audio:
say -o council/brief.aiff -f council/audio.txt

Put the file on your phone and play it in the gym, like Tobi, or on a walk. Anywhere else, any text-to-speech tool does the same job. OpenAI's speech endpoint returns mp3 by default.

02The multi-model workflow

The multi-model workflow, in three moves.

Different models for different roles, and a random pick for who writes the summary.

  • 1Pick three or four models from different labs.Tobi named Grok, ChatGPT, Opus and maybe Kimi, and said the list changes all the time. Use whatever is current and copy the names exactly as your provider lists them. Mixing labs matters because LLM judges score their own output above that of other models (Panickssery, Bowman and Feng, NeurIPS 2024). That paper is about models as judges. Using it to build a council is my reading of it, the same one the Reel makes.
  • 2Give the agent one way to reach them.Pick the route that fits what you already have.
  • No code. Open chat apps from three different labs. Paste your context and one role prompt into each. Roll a die to pick which app writes the summary, then paste all three answers into it. There is no key and nothing to install.
  • One key, many models. OpenRouter gives you one endpoint for every model. You choose the model in the model field, written as provider/model, and the slugs are listed on openrouter.ai/models. Tobi brings up OpenRouter in the same interview as a way to reach every model on one subscription.
  • A Claude-only test run. In Claude Code, a subagent file in .claude/agents/ has a model line: sonnet, opus, haiku, fable or a full model ID. That is one lab, so it is not the mixed panel, but it tests the flow before you add keys.
  • Ready-made. Andrej Karpathy's llm-council sends one question to several models through OpenRouter, has them rank each other's answers without names, then lets a fixed chairman model write the final one. Its README says it is provided as is and unsupported. It does not randomise the summariser.
  • 3Let a random pick choose the summariser.In Tobi's version the synthesis step is randomised, so no model gets the last word every time. Step 4 of the prompt makes the agent run one line of Python and use the answer, rather than choose for itself.
Two differences from the transcript. As I read it, Tobi runs each role against each model. The prompt gives each role one model, which means fewer calls. For his full version, change step 2 to run every role on every model, and read section 03 first. He also says the pooled synthesis is read, usually by the best model available, and that read is what comes back to him. The Reel skips that step. To copy it, send brief.md to your strongest model for a final read.

03Costs kept under control

Costs kept under control, six ways.

Tobi puts a run at 15 to 20 dollars in tokens. Two things move that number: how many calls you make and how much each call carries.

Save the council for decisions that earn it. Tobi uses his when a decision is really important, not for every question.

  • 1Count the calls before you run.Five or six roles on four models is 20 to 24 calls before the summary, if you read Tobi's description literally. The prompt in section 01 gives each role one model: four roles, four calls, plus one for the summary. Add a second model per role once the first run has earned it.
  • 2Keep every call small.Every call carries your context file, so keep it to one page. The prompt caps each answer at 300 words. Output costs more than input: on Anthropic's price list, an output token costs five times an input token on Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5.
  • 3Cache what repeats.When the same model reads your context more than once, cache it. On Anthropic's API, put the context first, the role prompt after it, and mark the end of the context with cache_control. A cache read costs a tenth of the base input price, less on the newest models, and the default cache lasts five minutes, so send the calls together. Writing the cache costs 1.25 times the base price, so it only pays when the same model gets several calls, as in Tobi's every-role-on-every-model version. Prompts under the model's minimum, 512 tokens on the newest models, are not cached, and nothing warns you.
  • 4Batch what can wait.Anthropic's Message Batches and OpenAI's Batch API both charge half the standard price in exchange for a 24 hour processing window. Anthropic says most batches finish within an hour. The role calls do not depend on each other, so they suit a batch. The summary needs their answers, so it goes in a second batch or a normal call. Queue it before bed and listen in the morning.
  • 5Match the model to the role.Prices differ a lot. On Anthropic's list on 9 October 2026, base input runs from $0.10 per million tokens for Haiku 5.5 (prompts up to 100,000 tokens) to $10 for Fable 5.1. My rule of thumb: give the cheaper tiers the roles that gather and check facts, and keep the strongest model for the roles where judgment is the job.
  • 6Cap the key and read the bill.OpenRouter lets you set a credit limit on a single API key. When it runs out, requests fail with a 402 error instead of billing you more, so give the council its own key and a limit you can live with. Every response also carries a usage object with prompt_tokens, completion_tokens and cost, which the last line of the prompt asks the agent to report. Do a test run with two roles before you scale up.

04What to do now

Pick one. Run it on a real decision.

It only pays off on a decision you are actually making. Run it before the big calls, listen to it in the gym or on a walk, and make it a habit.

  • If you want to try it today with nothing to install: run the no-code version from section 02 on one real decision.
  • If you use Claude Code or Codex: copy the prompt in section 01, fill the three brackets and give it a capped key.
  • If cost is what's stopping you: start with items 1 and 2 in section 03, then do a two-role test run.
  • If you would rather hear the answer than read it: run the say command in step 4 of section 01.
