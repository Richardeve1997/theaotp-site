01 · The prompt

One prompt. Three jobs.

This goes in your project's instructions, not in a chat. Claude uses it in every chat inside the project.

It gives Claude three jobs. Keep your files in one structure it can find its way around. Save new work and new uploads back into the right place. Review the whole thing so nothing goes stale or contradicts itself.

You manage the knowledge in this project. Treat the project files as a small wiki you keep organised, so you can find anything fast and nothing important gets lost between chats.

1. Keep one structure
Everything lives in three layers:
- index.md: one line per topic, saying what it covers and which summary file holds it. Read this first in every chat.
- Summaries: one short file per topic (clients.md, offers.md, brand.md). The key facts, decisions and open questions, with a pointer to the full documents behind them.
- Full documents: the originals I upload, left unchanged.
When you need context, read index.md, then the right summary, and open a full document only when the summary isn't enough. If the structure doesn't exist yet, build it from the files in this project and show it to me before you save it.

2. Save back after every piece of work
At the end of any chat where we decide something, learn something or make something, and whenever I upload a new document:
- Work out which topic it belongs to.
- Update that summary with what changed: the decision, the date and where it came from.
- Add or update its line in index.md.
- If it's a new topic, make a new summary and add it to the index.
If you can edit the project files, do it. If you can't, give me each updated file in full and tell me exactly which file to replace. Never leave important context sitting only in a chat.

3. Keep it clean
Every time you read a summary, check it against what you know now. When I ask for a review, or about once a week, go through the whole structure and:
- flag anything stale, with the date it was last true
- find facts that contradict each other and ask me which one is right
- merge duplicate topics and drop what's no longer useful
- keep each summary short enough to read in a minute
Show me the changes as a short list before you save them.

Rules
- Never delete an original document.
- Never invent a fact to fill a gap. Write "unknown" and ask me.
- Date every decision.
- Keep file names short and lowercase, like pricing.md.
The file names in it (clients.md, offers.md, brand.md) are examples. Claude names your topics from what you upload.
02 · Set it up

Set it up once. Three steps.

All of this happens in Claude on the web. Projects are on every plan, and a free account gets up to five.

  • 1Create the project.Click "Projects" in the left sidebar, or go straight to claude.ai/projects. Click "+ New Project" in the top right. Give it a name and a description. Claude can't see either, so write them for yourself.
  • 2Paste the prompt into the instructions.On the project page, click "Set project instructions". In the newer layout it's the pencil next to Instructions. Paste the prompt from section 01 and click "Save instructions".
  • 3Add your main documents.Click the "+" next to Files. Choose "Upload from device" for files, or "Add text content" to paste text in. Start with the things you explain to Claude over and over: your offer, your clients, your brand, the plan you're working to.
Why the rest of this guide exists: Anthropic's help centre says context is not shared between chats in a project unless it's added to the project knowledge. Your files carry over from chat to chat. The chats themselves don't.

On a paid plan, once your files get close to the context limit, Claude switches on RAG and searches your files instead of reading them all. Anthropic's advice for that mode is clear, descriptive file names. A short index and one summary per topic give it exactly that.

03 · First chat

Build the index. Before anything else.

Start a new chat inside the project and send this. Claude reads what you uploaded and shows you the structure before anything gets saved.

Read every file in this project's knowledge. Using the structure in your instructions, plan index.md and one short summary file per topic. Show me the index and the list of summaries first. Once I say go, give me each file in full with its exact file name so I can add it to the project.

Read the index it shows you. Merge topics that belong together, rename anything unclear, then tell it to go.

Save each file it gives you under the name it used (index.md, clients.md and so on) and add it with "Upload from device". If you'd rather paste, "Add text content" in the same menu works too. Leave your original documents where they are. The prompt tells Claude never to delete one.

04 · Save back

Save it back. Every time.

Only what's in the project files carries over to the next chat. So end every useful chat with this.

Save back what we did in this chat. Tell me which topic it belongs to, then give me the updated summary file and the updated index.md in full, with the exact file names to replace. Date anything we decided.

Just uploaded a new document? Say so in the chat ("I just added pricing.pdf") and send the same message. Claude works out where it belongs and updates the summary and the index.

Swapping in the new file

Here's the honest bit. Anthropic's help docs say you can add and remove project files at any time. They don't say Claude can edit your project files from a chat. So in a normal project, Claude hands you the updated file and you swap it in. The prompt already covers this: if Claude can't edit the files, it gives you each one in full and tells you which file to replace.

  • 1Copy the updated file.Take the whole file Claude gives you, not just the lines that changed.
  • 2Remove the old version.Delete that file from Files on the project page. Only the summary or index it replaces, never an original document.
  • 3Add the new one under the same name.Use "Upload from device" or "Add text content", same as before.
Anthropic is also rolling out a new version of projects in beta, starting with Claude Code for some Pro and Max users. There, the project's Library collects the files you add and the files Claude produces. If your setup lets Claude write to the project's files, the prompt tells it to do that itself.
05 · Once a week

Review it. Before it goes stale.

An old fact is worse than a missing one, because Claude will use it without blinking. Once a week, start a new chat in the project and send this.

Run the weekly review from your instructions. Go through index.md and every summary. List anything stale with the date it was last true, any facts that contradict each other, and any topics to merge or drop. Ask me which version is right for each contradiction. Once I've answered, give me every changed file in full with its exact file name.

Answer its questions, then swap the changed files in the same way as section 04. Put it in your calendar. This is the step that keeps the rest useful.

06 · Why this works

Not my idea. Karpathy's.

The structure comes from Andrej Karpathy's LLM wiki. I didn't invent it. I turned it into a prompt for Claude Projects.

His gist describes three layers. Raw sources that never change. A wiki of markdown pages the model writes and keeps up to date. And a schema that tells the model how the wiki is organised. An index.md is the catalogue it reads first, and a regular "lint" pass looks for contradictions between pages and claims that newer sources have replaced.

In his gistIn your project
Raw sourcesThe documents you upload, left unchanged
The wikiindex.md plus one short summary per topic
The schemaThe prompt in your project instructions
LintThe weekly review in section 05

Claude reads a short index, then the one summary it needs, and opens a full document only when the summary isn't enough. That's less to search and less to get wrong. His point is that the tedious part of a knowledge base is the bookkeeping. You hand that to Claude and keep the decisions.
