01What this does

Claude rents a graphics card for the job, then switches it off.

You keep Claude Code on your own computer. When a job is too heavy for it, Claude rents a graphics card from RunPod by the second, runs the job there, brings the files home and deletes the machine.

Your Claude session, your chat and your Claude plan stay exactly where they are. Only the heavy command runs on the rented machine. RunPod bills you for that directly, so it's a second bill: your Claude plan doesn't cover it.

I tested it on 22 November. Claude rented one NVIDIA RTX 3080 Ti on RunPod's Community Cloud at $0.18 an hour and transcribed five of my finished Reels on it. Here's the receipt, next to my Mac (an M4 with 16 GB).

02Setup

Four steps, then plain English.

You need a RunPod account with some credit, one line in your terminal and a sign-in. After that you ask Claude in plain English.

  • 1Make a RunPod account and add credit

    New users can start with $10. To deploy a Pod you need at least an hour of credit for that setup. Credit is non-refundable, so start small.

  • 2Add RunPod's MCP server to Claude Code

    Paste this into your terminal. It adds RunPod's hosted server for every project on your computer.

    claude mcp add --transport http runpod -s user https://mcp.runpod.io/
  • 3Sign in with /mcp

    Open Claude Code, type /mcp, pick runpod and sign in with your RunPod account. The sign-in is OAuth, so no API key sits on your computer.

  • 4Ask Claude for the job

    Paste a prompt from section 03. Claude picks the card, creates the Pod, runs the job, brings the files back and deletes the Pod.

If you'd rather use an API key, RunPod also runs the server locally: claude mcp add runpod --scope user -e RUNPOD_API_KEY=... -- npx -y @runpod/mcp-server@latest. I used the hosted one.

03The prompt

The exact prompt I used.

This is the brief that ran the test. Most of it is about money and safety: one Pod, a spend limit, no storage that bills while stopped, and a check at the end.

The exact prompt I used 
Run a first, small RunPod test. Use the RunPod MCP tools. Transcribe the audio of five of my finished videos on a single cheap GPU, and time it against my Mac. Extract mono 16 kHz WAVs locally with ffmpeg. On the Pod, use faster-whisper large-v3 on CUDA.

Cost and safety rules: use one Pod only, the cheapest suitable GPU on Community Cloud (an RTX 4090 or similar, under about $0.70 an hour). Use container disk only: no network volume, which bills while stopped. Total spend under US$1. Terminate the Pod the moment results are back. Then list Pods and volumes again and confirm nothing is running or left over. Do not change account settings, add SSH keys, buy credit or create API keys.

Getting files in and out: prefer what the MCP tools or the Pod's start command support, or a public HTTPS endpoint the Pod exposes. Don't upload my files to any third-party host.

Write up the GPU and price per hour, the times, the actual cost from the billing view or the API, and exactly how files moved in and out.

Claude tried an RTX 4090 first, found none in stock and took the RTX 3080 Ti at $0.18 an hour. The rules held: one Pod, no volume, and $0.0114 spent. Claude deleted the Pod 3 min 50 s after it created it.

The version to adapt · for your own job

Same safety rules, pointed at a business job. This one is set up for a folder of sales-call recordings. Swap in your folder, and raise the spend limit only once you've seen what a first run costs.

Use the RunPod MCP tools to transcribe the call recordings in [your folder] on one rented GPU.

First, on my computer, convert each file to a mono 16 kHz WAV with ffmpeg. On the Pod, use faster-whisper large-v3-turbo on CUDA with vad_filter=True and condition_on_previous_text=False, and save one JSON transcript per recording, with word timings.

Cost and safety rules: use one Pod only, the cheapest NVIDIA card with at least 10 GB that is in stock on Community Cloud. Tell me its price per hour before you create it. Use container disk only: no network volume, which bills while stopped. Total spend under US$1. Terminate the Pod the moment the results are back on my computer. Then list Pods, queued Pods, network volumes and global volumes, and confirm they are all empty. Do not change account settings, add SSH keys, buy credit or create API keys.

Getting files in and out: use what the MCP tools support, or an HTTPS port the Pod exposes, with a random token in the path. Don't upload my files to any third-party host.

When it's done, tell me the GPU and its price per hour, how long the job took, and the actual cost from my balance before and after.
Your recordings leave your computer for the length of the job. That was fine for my own Reels. If they're client calls, check you're allowed to send them to a cloud machine first.
04The shutdown check

It bills until it's off.

That's the catch. A Pod that nobody stops keeps charging, so end every job by asking Claude to prove nothing is still running.

Here's what keeps billing, from RunPod's billing docs. Pods and volumes bill until something stops them. A network volume bills even while it's stopped. The default spend limit is $80 an hour across the account, which is a lot of money for a job that forgot to switch off.

Paste this after every job 
Using the RunPod MCP tools, list my Pods, queued Pods, network volumes and global volumes, and confirm each list is empty. Then read my balance and tell me the number. If anything is still running or stored, tell me what it is and what it costs per hour, and wait for my yes before you delete it.

The balance is the number to trust straight away: the itemised billing line still hadn't posted about six minutes after the Pod was gone, so check that the next hour.

Container disk is erased when a Pod stops, and if your balance hits $0, every Pod stops and any Pod without a network volume loses its data. So copy your results home before anything else.
05How it ran

No SSH, no extra tools.

Claude ran everything through the MCP server. The files moved over HTTPS through a port the Pod opened, behind a random token.

The MCP's exec-pod tool runs one command inside the Pod and returns its output. It waits at most 25 seconds per call, so long jobs start in the background with nohup ... & and later calls read the log. The Pod exposed port 8000/http, which RunPod serves at https://<podId>-8000.proxy.runpod.net/, and a 25-line file server on the Pod only answered under a random 32-character token.

  • 1Make the audio small, then create the Pod

    Each video becomes a 16 kHz mono WAV on the Mac: ffmpeg -i in.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le out.wav. Then create-pod: Community Cloud, the cheapest NVIDIA card with at least 10 GB in stock, image runpod/pytorch:1.0.2-cu1281-torch280-ubuntu2404, 30 GB container disk, port 8000/http, no volume.

  • 2Write the two scripts on the Pod

    With exec-pod, Claude writes the file server and the transcriber (both below), starts the server with the token and runs pip install faster-whisper.

  • 3Upload the audio

    curl -T each WAV to https://<podId>-8000.proxy.runpod.net/<token>/in/<name>.wav. Five files, 11.4 MB, took 16 seconds, and the checksums on the Pod matched the Mac.

  • 4Transcribe and pull the results back

    Start the transcriber in the background, read its log until it says DONE, then curl each JSON file back from /<token>/out/.

  • 5Delete the Pod

    delete-pod the moment the files are home, then run the shutdown check from section 04.

The proxy address is public while the Pod is alive, and the token in the path is the only lock. That's one more reason to keep a Pod's life to minutes. Mine was gone four minutes after it started.
The file server · /work/srv.py 
import os, sys
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
TOK = sys.argv[1]
class H(BaseHTTPRequestHandler):
    def _path(self):
        parts = self.path.strip("/").split("/")
        if len(parts) != 3 or parts[0] != TOK or parts[1] not in ("in", "out") or "/" in parts[2] or parts[2].startswith("."):
            return None
        return os.path.join("/work", parts[1], parts[2])
    def do_PUT(self):
        p = self._path()
        if not p: self.send_response(404); self.end_headers(); return
        n = int(self.headers.get("Content-Length", 0))
        with open(p, "wb") as f:
            f.write(self.rfile.read(n))
        self.send_response(201); self.end_headers(); self.wfile.write(b"ok\n")
    def do_GET(self):
        p = self._path()
        if not p or not os.path.isfile(p): self.send_response(404); self.end_headers(); return
        b = open(p, "rb").read()
        self.send_response(200); self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)
    def log_message(self, *a): pass
os.makedirs("/work/in", exist_ok=True); os.makedirs("/work/out", exist_ok=True)
ThreadingHTTPServer(("0.0.0.0", 8000), H).serve_forever()
The transcriber · /work/tx.py, as it ran 
import glob, json, os, sys, time, wave
import numpy as np
t0 = time.time()
from faster_whisper import WhisperModel
model_name = sys.argv[1] if len(sys.argv) > 1 else "large-v3"
m = WhisperModel(model_name, device="cuda", compute_type="float16")
res = {"model": model_name, "load_s": round(time.time() - t0, 2), "files": []}
for p in sorted(glob.glob("/work/in/*.wav")):
    s = time.time()
    w_ = wave.open(p); a = np.frombuffer(w_.readframes(w_.getnframes()), np.int16).astype(np.float32) / 32768.0
    segs, info = m.transcribe(a, language="en", beam_size=5, word_timestamps=True, vad_filter=False)
    segs = list(segs)
    el = time.time() - s
    stem = os.path.basename(p)[:-4]
    out = {"segments": [{"s": round(x.start, 2), "e": round(x.end, 2), "text": x.text.strip(),
           "words": [{"w": w.word, "s": round(w.start, 2), "e": round(w.end, 2), "p": round(w.probability, 3)} for w in (x.words or [])]} for x in segs]}
    json.dump(out, open(f"/work/out/{stem}.{model_name}.json", "w"))
    res["files"].append({"file": stem, "audio_s": round(info.duration, 2), "tx_s": round(el, 2)})
    print(stem, round(info.duration, 1), round(el, 2), flush=True)
res["total_s"] = round(time.time() - t0, 2)
json.dump(res, open(f"/work/out/timings.{model_name}.json", "w"), indent=1)
print("DONE", res["total_s"])

For a batch, change vad_filter=False to vad_filter=True and add condition_on_previous_text=False in the same call. Section 06 says why.

06Gotchas

What went wrong on the real run.

Nothing broke the bill, but four things would trip you up on your first job.

  • 1The card you ask for may not be in stock

    The catalogue showed no RTX 4090s on Community Cloud. An RTX 4080 SUPER showed low stock at $0.28 an hour, but create-pod came back with "no longer any instances available". The RTX 3080 Ti did the job at about half the 4090's price, and its 12 GB was plenty: the GPU memory sat at about a quarter used. Tell Claude a price ceiling, not one card.

  • 2The audio reader crashed

    faster-whisper's own audio reader failed with TypeError: open() got an unexpected keyword argument 'metadata_errors', because the image's PyAV was older than faster-whisper expects. Reading the WAV with Python's wave module fixed it (that's in the transcriber above), and pip install -U av would also work. It cost about 70 seconds.

  • 3large-v3 repeated itself on one file

    On one Reel, large-v3 repeated a sentence and wrote the closing line three times in the last half second. That's Whisper's known repetition loop when it reads a whole file with no voice detection and condition_on_previous_text left on. For a batch, pass vad_filter=True and condition_on_previous_text=False, or use large-v3-turbo, which was clean on the same file.

  • 4Product names still come out wrong

    Every run, on both machines, wrote "Artcraft" for AgentCraft. A faster computer doesn't fix spelling, so keep your usual find-and-replace for names.

07RunPod or Vercel

Graphics card jobs, or everything else.

RunPod rents graphics cards. Vercel Sandboxes rent plain cloud Linux machines with no graphics card. Pick by what the job needs.
