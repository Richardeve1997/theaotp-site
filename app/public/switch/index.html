01 · Install

Get VS Code and both CLIs.

The chat apps lock you into one model at a time. You'll work in VS Code instead, with both CLIs running in its terminal, side by side, on the subscriptions you already pay for.

Download VS Code (free), open it, then install both CLIs from its terminal:

npm install -g @anthropic-ai/claude-code npm install -g @openai/codex

Run claude and log in with your Claude account, then run codex and log in with your ChatGPT account. Two separate quotas, one project. That's the whole trick.

03 · Prompt 1

Build the file system both models can read.

One folder, one source of truth. CLAUDE.md holds the instructions, AGENTS.md is a thin adapter that points Codex at it, and one shared skill tree serves both. Open a terminal in VS Code, start claude (or codex) in the folder you want as your workspace, and paste this.

You are setting up my personal AI file system: one folder that holds my context, skills, and
instructions, and works with both Claude Code and the Codex CLI on the same project at the same
time.

Before you write anything, interview me. Ask me these five questions, one message, numbered, then
wait for my answers:

1. What do you do, and what should AI know about your role?
2. What are the two or three projects or areas you'll work on in this folder?
3. What tools and platforms do you live in day to day?
4. How do you like things written? (tone, length, formatting rules, anything you hate)
5. What do you want AI to take off your plate first?

Once I answer, build this exact structure:

1. `CLAUDE.md` at the root. This is the single canonical instruction file for the whole
   workspace. It contains: who I am and how I work (from my answers), a map of every folder below
   and what belongs in it, my writing rules, and this standing rule: "CLAUDE.md is the source of
   truth. AGENTS.md is a thin adapter for Codex and never duplicates this file."

2. `AGENTS.md` at the root. A short adapter for the Codex CLI, under 25 lines. It must say:
   read CLAUDE.md in full and treat it as canonical; the skill tree lives in `.claude/skills/`
   and is shared between both tools, never copied; if the two files ever disagree, CLAUDE.md
   wins; durable changes get written back to the canonical owner, not into this file.

3. `.claude/skills/` as the canonical skill tree. Create one starter skill,
   `.claude/skills/README.md`, explaining that each skill is a folder with a `SKILL.md` that says
   when to use it and exactly how to do the job.

4. `.agents/skills` as a symlink pointing at `.claude/skills`, so Codex discovers the exact same
   skills. On a system without symlinks, write `.agents/skills/README.md` pointing at the
   canonical tree instead.

5. `context/` for durable knowledge: `context/about-me.md` (from my answers) and
   `context/preferences.md` (my writing and working rules). CLAUDE.md should point here rather
   than restating everything.

6. `projects/` with one subfolder per project I named, each holding a short `README.md` stating
   the goal and current state.

7. `inbox/` for raw notes and ideas I drop in for AI to process later.

When you're done, verify your own work: confirm the symlink resolves, confirm AGENTS.md is under
25 lines and contains no duplicated content, and print the folder tree with a one-line
explanation of each entry. Then tell me the one-sentence rule for keeping this system healthy:
every durable instruction lives in exactly one file, and both tools read the same files.
04 · Prompt 2

Create the skill that makes them work together.

Run this once, after Prompt 1. It creates a reusable handover skill: Claude plans and reviews, GPT 5.6 implements through the Codex CLI, and you pay Anthropic prices for judgement and OpenAI prices for keystrokes. From then on you just say "hand this to 5.6" and the whole workflow fires.

Create a reusable skill called `handover` in my file system so Claude and the Codex CLI work
together on any task without me retyping the workflow.

Write `.claude/skills/handover/SKILL.md` with:

1. Frontmatter: `name: handover` and a description tuned so the skill fires when I say things
   like "hand this to 5.6", "have codex build this", "run the loop on X", "plan execute review
   this", or "use both models on this".

2. The workflow the skill runs, exactly this shape:

   STEP 1: PLAN. Claude writes a complete, self-contained spec to `specs/<task-slug>.md`.
   Codex cannot see the conversation, so the file must stand entirely on its own: the goal, the
   constraints, the files to create or change, what NOT to touch, and a numbered list of
   acceptance checks that can be verified from the terminal. Show me the spec and wait for my
   approval before continuing.

   STEP 2: EXECUTE. Hand the spec to GPT 5.6:
   `codex exec -s workspace-write "Read specs/<task-slug>.md and implement it exactly. Do not
   expand scope. Do not refactor unrelated code. When you finish, list every file you changed
   and how each acceptance check is met."`
   Never edit files while Codex is running.

   STEP 3: REVIEW. Ignore Codex's summary of its own work. Read the actual diff. Run every
   acceptance check from the spec. Be adversarial: look for scope creep, broken edge cases, and
   anything the spec asked for that quietly didn't happen.

   STEP 4: ITERATE. If the review fails, send precise, file-level feedback back into the same
   Codex session: `codex exec resume --last "<exactly what is wrong and what to change>"`.
   Maximum three iterations; after that, finish the remainder directly and say what was fixed.

3. An effort dial: when I say "on low", "on medium", "on high", or "flat out", append
   `-c model_reasoning_effort=<low|medium|high|xhigh>` to the codex command. Default to medium
   for mechanical work and high for anything with design decisions.

4. Standing rules inside the skill: specs are self-contained files; one spec per task; the
   reviewer never rubber-stamps; report what shipped, what Codex built, and what was corrected,
   with the acceptance checks and their results.

Then verify `.agents/skills/handover/SKILL.md` resolves through the symlink so the Codex CLI
discovers the same skill, and show me the finished SKILL.md.
