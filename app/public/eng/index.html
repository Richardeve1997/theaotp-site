02Matt's skills

Install Matt's skills.

Two ways in. Pick the one that matches your agent.

Claude Code. Run this inside a session:

/plugin install mattpocock-skills

Codex and other agents. This copies the skills into your repo as plain files you own:

npx skills@latest add mattpocock/skills

The installer lets you choose which skills to take. Make sure setup-matt-pocock-skills is one of them.

Then run this once per repo. It asks which issue tracker you use, which labels you put on tickets and where to save docs:

/setup-matt-pocock-skills

Start with /grill-with-docs for code, or /grill-me for anything else. The agent asks you detailed questions about what you're building before it writes a line. Matt calls them his most popular skills and says to use them every time you want to make a change.

03Lauren's pstack

Install pstack.

pstack is a Cursor plugin. Two steps and you're running.

In Cursor, add the plugin:

/add-plugin pstack

Run /setup-pstack once. It asks you to pick a reasoning budget and which models you want. After that, use /poteto-mode whenever a task needs rigor. It reads your request, picks a playbook and runs the other skills as the task needs them. An example from the README:

/poteto-mode this pr has a subtle bug where the scroll drifts every 750ms even when idle. repro first, then fix and verify.

Stuck? Ask /poteto-help. The pstack guide walks you through a first real task, from setup and prompting through verification and overnight runs.

04The two habits

The two habits from the talk.

Neither needs a new tool. Both change how much you can trust your agent.

  • 1Let your agent test its own work.Without a browser, your agent can't click through your app, so you end up copy-pasting errors back and forth. Give it a browser and it can try the app like a user, then show you proof.
claude mcp add playwright npx @playwright/mcp@latest

That adds Microsoft's Playwright MCP to Claude Code, so the agent can drive a real browser. Then give it a standing rule:

Test it like a user. Click through the app yourself and show me screenshots before you say it's done.

pstack also has /create-verification-skill. It builds a verify skill inside your project, for an app that has no scripted way to prove it works.

  • 2Block out time every week to improve your setup.Look at how you actually worked, find what slowed you down and fix it. You don't have to do the digging by hand. Ask your agent to read your past conversations:
Review my past work. Find bottlenecks. Propose fixes.

pstack has two skills for this. /recall rebuilds your recent context from your own chat history. /reflect turns a long task into a skill edit, so the next run starts from what you learned.

05What to do now

Pick one. Start today.

Installing is the easy part. Using it on a real task is what shows you the difference.

  • If you use Claude Code or Codex: install Matt's skills in section 02, run the setup, then try /grill-with-docs on your next change.
  • If you use Cursor: add pstack in section 03 and run /poteto-mode on your next task.
  • If your agent says it's done and it isn't: give it the browser from habit 1 in section 04.
  • If your setup feels stale: block out an hour this week and paste the review prompt from habit 2.

See what's possible. Then build it.
