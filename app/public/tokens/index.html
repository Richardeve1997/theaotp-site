01 · What you get

A quota readout on every turn.

Not a token counter. A plan-quota bar: how much of your session and your week you have left, in the status line you're already looking at, refreshed as you work.

Opus 5 main ctx:14% Session 62% left (14:30) | Week 28% (Thu) | Opus wk 9%

Green above 30% left, amber at 30 and under, red at 10 and under. The point isn't the number, it's the intuition you build by seeing it a hundred times a day. You learn which tasks are expensive before the week runs out, not after.

Before you start: these prompts write to ~/.claude/ and read your OAuth token from the macOS Keychain. Both prompts are written to never print, log, or copy that token. Read what they build before you run it, the same as you should with anything that touches credentials.
02 · Prompt 1

The Claude Code usage bar.

Open Claude Code anywhere and paste this whole thing. It builds the reader, the wrapper, wires up your settings, and then proves to you that it works before it claims to be done.

Add a live usage bar to my Claude Code status line so I can see how much of my plan I
have left without running /usage.

Build it exactly as specified below. Verify each step before moving to the next one.
Never print, log, echo, or copy my access token into any file or any output.

## What you are building

A status line that renders on every turn and shows, left to right: the model name, the
git branch, the context-window percentage, then how much of my plan quota is left for
the current session and the current week.

## Step 1 - the usage reader

Create `~/.claude/statusline-usage.py`. Python 3, standard library only (json, os,
subprocess, sys, time, urllib.request, datetime). No pip installs.

It must:

1. Read the OAuth access token WITHOUT ever printing it. Try the macOS Keychain first:
   run `security find-generic-password -s "Claude Code-credentials" -w`, parse stdout
   as JSON, take `["claudeAiOauth"]["accessToken"]`. If that fails for any reason, fall
   back to reading `~/.claude/.credentials.json` and taking the same nested key. If
   neither works, return None and degrade gracefully. On Linux the Keychain call will
   always fail and the file fallback is the real path, so keep both branches.

2. Call `GET https://api.anthropic.com/api/oauth/usage` with exactly two headers:
   `Authorization: Bearer <token>` and `anthropic-beta: oauth-2025-04-20`.
   Use a 5 second timeout. This is the same endpoint the /usage command reads.

3. Cache aggressively. The status line re-renders constantly and must never hammer the
   API. Write the response to `~/.claude/.usage-statusline-cache.json` in the shape
   `{"fetched_at": <unix time>, "data": <response>}` and chmod it 0600. Serve from
   cache whenever it is under 60 seconds old. On ANY fetch failure, serve the stale
   cache rather than showing nothing. A network blip must never break my status line.

4. Parse the response. It contains a `limits` array. Each entry has:
   - `kind`: one of `session`, `weekly_all`, `weekly_scoped`
   - `percent`: the percentage USED, so remaining is `100 - percent`
   - `resets_at`: an ISO timestamp
   - `group`: `weekly` on the weekly limits
   - `scope.model.display_name`: present only on `weekly_scoped`, naming the model
     that limit applies to

5. Render one segment per limit, joined by ` | `:
   - `session`       -> `Session 62% left (resets 14:30)`
   - `weekly_all`    -> `Week 41% (Thu)`
   - `weekly_scoped` -> `Opus wk 23%`
   Convert reset times into MY local timezone. For weekly limits show the weekday
   abbreviation when the reset falls on a different day, otherwise HH:MM. For the
   session limit always show HH:MM. If a timestamp will not parse, show `?` rather
   than raising.

6. Colour each percentage with raw ANSI escapes: green `\033[32m` above 30% left,
   yellow `\033[33m` at 30 or below, red `\033[31m` at 10 or below. Dim `\033[2m` the
   model name and the reset times. Emit reset `\033[0m` after every coloured span.

7. Read the Claude Code JSON payload from stdin and pull `model.display_name` to prefix
   the line. If stdin is empty or unparseable, carry on without the model name rather
   than failing.

8. If there is no usable data at all, print `<model> | usage unavailable` dimmed,
   rather than crashing or printing an empty line.

## Step 2 - the status line wrapper

Create `~/.claude/statusline-command.sh`, bash. Claude Code pipes a JSON object into it
on every render. Using `jq`, pull out:

- `.model.display_name`, falling back to "Unknown Model"
- `.workspace.current_dir`
- `.context_window.used_percentage`

Assemble the line from: the model name; the current git branch if the working directory
is inside a repo (resolve it with `git -C "$cwd" rev-parse --abbrev-ref HEAD`, and emit
nothing if that fails); `ctx:NN%` from the context percentage rounded to a whole number;
and finally the Python script from Step 1, called as

    usage=$(echo '{}' | python3 "$HOME/.claude/statusline-usage.py" 2>/dev/null)

Append the usage segment only when it came back non-empty, so any failure degrades to a
shorter line instead of a broken one. Finish with `printf '%s'` rather than echo so no
trailing newline is emitted.

## Step 3 - wire it up

Edit `~/.claude/settings.json`, preserving every existing key. Read the file, parse it
as JSON, add the key below, write it back formatted. If the file does not exist, create
it containing only this:

    "statusLine": {
      "type": "command",
      "command": "bash /Users/<me>/.claude/statusline-command.sh"
    }

Use my real absolute home path, not a tilde. Tilde does not expand here.

## Step 4 - verify before you tell me it works

Do not report success until all five of these pass, and show me the output of each:

1. `chmod +x` both scripts.
2. `echo '{}' | python3 ~/.claude/statusline-usage.py` prints real percentages, not
   "usage unavailable". If it does print that, diagnose it: token not found, endpoint
   unreachable, or an unexpected response shape. Say which.
3. A realistic payload through the wrapper renders correctly:
   `echo '{"model":{"display_name":"Opus 5"},"workspace":{"current_dir":"'$PWD'"},"context_window":{"used_percentage":12.4}}' | bash ~/.claude/statusline-command.sh`
4. `~/.claude/.usage-statusline-cache.json` exists and is mode 600.
5. My token appears in NO file you created and in none of your output. Grep to confirm.

Then tell me the exact line I will see, and remind me the status line only redraws on a
new turn, so I need to press enter once in an open session before it appears.
03 · Prompt 2

The same thing for Codex.

The Codex CLI has no status-line hook, so this one works differently, and the prompt is written to stop the model inventing a config option that doesn't exist. Codex does write its rate limits to disk. This reads them.

Add a usage readout for the Codex CLI.

Important, and do not work around it: unlike Claude Code, the Codex CLI has NO
status-line hook. There is nothing to configure in `~/.codex/config.toml` for this. Do
not invent a setting, and do not add one speculatively. Codex does write its rate-limit
state to disk, so build a standalone command instead.

## Where the data actually lives

Codex writes a rollout log per session at
`~/.codex/sessions/YYYY/MM/DD/rollout-<timestamp>-<uuid>.jsonl`. Lines in that file
carry a `rate_limits` object shaped like this:

    "rate_limits": {
      "limit_id": "codex",
      "primary":   {"used_percent": 92.0, "window_minutes": 43200, "resets_at": 1782974598},
      "secondary": null,
      "credits": null,
      "plan_type": "free"
    }

VERIFY this on my machine before writing any code. Find the most recently modified
rollout file and grep it:

    grep -o '"rate_limits":{[^}]*}[^}]*}' <that file> | tail -1

If the shape differs from what I have described above, follow what you actually find
and tell me exactly how it differed. Do not code against my description if the machine
disagrees with it.

## Build `~/.local/bin/codex-usage`

Python 3, standard library only. It must:

1. Find the most recently MODIFIED `rollout-*.jsonl` anywhere under
   `~/.codex/sessions/`, not the newest by filename. Filenames sort by session start
   time, which is not the same as last write, and the freshest numbers live in whichever
   session was most recently active.

2. Read that file BACKWARDS from the end and stop at the first line carrying a non-null
   `rate_limits`. Do not parse the whole file; these logs get large.

3. Print remaining percentage as `100 - used_percent` for `primary`, and for `secondary`
   as well when it is not null. Label each by its window: convert `window_minutes` into
   something human (43200 = 30d, 10080 = 7d, 300 = 5h) and use that in the label, so it
   reads like `Codex 30d: 8% left`.

4. Convert `resets_at` from a unix epoch into my local time and show it.

5. Include `plan_type` in the output so I can see which plan the numbers describe.

6. Print `Codex: no usage data yet` and exit 0 when no rollout file carries rate limits,
   so it is safe to call from a shell prompt.

## The honesty requirement

These numbers are a snapshot from the last Codex API response, not a live reading. If I
have not run Codex for three days, they are three days stale. Print the age of the
reading alongside it, like `(as of 14:32, 2h ago)`, so I can never mistake a stale
number for a current one. Do not smooth this over or round it away.

## Verify

Run it, and show me its output next to what `codex` itself reports for rate limits, so
I can confirm the two agree. Then tell me the single line I could add to my shell config
to put it in my prompt, but do NOT edit my shell config unless I say yes.
04 · If it misbehaves

Four things that go wrong.

  • Nothing appears. The status line only redraws on a new turn. Press enter once in an open session.
  • "usage unavailable". The token lookup failed. Run echo '{}' | python3 ~/.claude/statusline-usage.py on its own and read the error. Usually it means you're signed in with an API key rather than a Claude subscription, and there's no plan quota to report.
  • The tilde didn't expand. settings.json needs the real absolute path to the script. ~ is not expanded there.
  • Codex numbers look frozen. They are. They only update when Codex next talks to the API. That's why the prompt makes it print how old the reading is.

Both scripts fail soft by design. If the endpoint is down or your token rotates, you lose the usage segment and keep the rest of the status line. Nothing blocks your session.
