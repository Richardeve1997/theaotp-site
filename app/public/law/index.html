01The repo

The repo from the Reel.

Claude for Legal is Anthropic's open-source set of legal plugins for Claude. One address puts all of them on your list to install.

I didn't build these and I earn nothing from them. Anthropic made them and announced them on 12 May 2026. Every command on this page comes from the repo's own pages, and the Claude Desktop steps come from Anthropic's help pages. All of it was checked against those pages on 12 October 2026.

The README lists 93 named agents across 12 practice-area plugins. Each agent does one job from a legal team's week, like screening a brand name for trademark problems, reviewing an offer letter or flagging risky marketing claims. A plugin is an add-on that gives Claude those skills. You install the plugins you want, ask Claude for the job and review what it drafts.

What they don't do. The README says every output is "a draft for attorney review" and "not legal advice, not a legal conclusion, not a substitute for a lawyer." It says a lawyer reviews and verifies whatever leaves the building, and that the plugins "make that review faster; they do not replace it."
This is not legal advice. This page explains a tool and how to set it up. The agents can be wrong, and they don't replace a lawyer. Have a lawyer look at anything that matters before you act on it: a contract you're about to sign, a person you're about to hire, a name you're about to build a business on. Check every fact and citation yourself.

03Install

Add the repo, then install four plugins.

Anthropic put everything in one repo. You add that repo to Claude once as a marketplace (a catalogue of plugins), then install the plugins you want from it.

1. Add the marketplace

Open the Claude Desktop app. If you see a Cowork tab, click it. Click Customize in the left sidebar and open the Plugins tab. Then click Add and choose Add marketplace.

You get two options. Under Browse Anthropic sources, pick Legal, then click Add and Done. Or choose Add from a repository and paste the repo address:

https://github.com/anthropics/claude-for-legal

You can also type just anthropics/claude-for-legal, which is what Anthropic's own install video types into that box. Check the owner: it is anthropics, Anthropic's own account. Anthropic's help page says to install plugins only from sources you trust.

Claude then syncs the repo. In Anthropic's video that takes about half a minute, and a message says it is still syncing. Wait for it.

2. Install your plugins

Back on the Plugins tab, open Discover. Select a plugin, read what it contains, then click Add. Do that for the four in section 04. You should see Commercial legal, Employment legal, IP legal and Product legal among the plugins. In Cowork, a new plugin's skills, commands and agents load the next time you start a task, so start a fresh one.

3. Check it worked

Start a task and type /. Commands from your new plugins should appear in the list, named like /ip-legal:clearance. In Cowork you can also type the full command, /plugin-name:command.

On a Team or Enterprise plan, an admin may have to switch on the Legal source first. Anthropic's Claude Academy page says an admin does that once from the organization's plugin settings, and that on an individual plan you can do it yourself. If Add doesn't take you straight to the plugin, that is usually the missing step.
Anthropic's pages describe the menus in different ways. The steps above follow its help page on plugins, as it read on 12 October 2026. Its plugin docs say Add, then Add marketplace, then an owner/repo address. The repo's README says Cowork tab, Customize, Browse plugins. The install video the README links to clicks the + next to Personal plugins, then Add marketplace. Anthropic is also rolling Cowork into the main Claude app for Pro and Max plans, so your screen may not show separate Chat and Cowork options. If a button has a different name on your screen, use the closest match. They all end in the same place: the repo added as a marketplace, then the plugins added from it.

Or in Claude Code

If you already work in a terminal with Claude Code, three commands do the same job. Type them inside a Claude Code session, one at a time. First, add the marketplace. The README's line has a blank where the repo goes, and Claude Code's docs write a GitHub repo as owner/repo:

/plugin marketplace add anthropics/claude-for-legal

Second, install a plugin. This is the README's own example, Commercial legal:

/plugin install commercial-legal@claude-for-legal

For another plugin, change the name before the @ to employment-legal, ip-legal or product-legal. If it asks where to install, pick user scope, so the plugin can read files from any folder. Then close and reopen Claude Code: the repo's quick start calls that step "not optional". Third, run the setup interview from section 05:

/commercial-legal:cold-start-interview
If it doesn't work. The quick start says "Command not found" after an install means you skipped the restart. If Claude says it can't read a file, the plugin was most often installed for one project only, so reinstall it at user scope.

05Setup interview

Do the setup interview first.

Every plugin starts with a short interview that teaches it how your business works. The README calls skipping it "the single most common reason" for generic answers.

  • 1Run it for each plugin.

    In a task, type the interview command for each plugin you installed:
    /commercial-legal:cold-start-interview
    /employment-legal:cold-start-interview
    /ip-legal:cold-start-interview
    /product-legal:cold-start-interview

    Without a profile, a command stops and tells you to run setup first.

  • 2Pick quick or full.It asks first. Quick takes about 2 minutes and fills in working defaults. Full takes 10 to 20 minutes and asks for real documents, like five to ten signed agreements for Commercial or your handbook for Employment. Pick quick to start. You can add the full version later with --full. If you need to stop part way, say "pause". Run the command again later and it picks up where you left off.
  • 3Say who is using it.

    The choices are lawyer, non-lawyer with attorney access, and non-lawyer without regular attorney access. A founder fits the second.

    Pick either non-lawyer option and it changes how it works, and says so once. It writes its results as research for an attorney to review, not as verdicts. It pauses before steps with legal consequences, like signing a contract, making an offer, publishing a claim or accepting a renewal, and asks whether an attorney has reviewed it. It also writes a short brief to bring to one.

    If you pick the third, it adds how to find a lawyer: your state bar or law society runs a referral service.

  • 4Answer its few questions.Quick setup asks a short set for each plugin (table below). Once the first plugin has saved your company details, the other three skip those questions.
  • 5Let it write your profile.The interview saves what it learned as a plain-English file on your computer, your practice profile, and every command reads it first. You can open it and edit it, run the interview again or tell a command to record a new position. The README puts it at ~/.claude/plugins/config/claude-for-legal/<plugin>/CLAUDE.md. The Employment files hold staff details, and the README says to keep that folder backed up and access-controlled.
PluginWhat quick setup asks
Commercial legalYour role, setting and jurisdiction, and whether you are setting rules for contracts where you sell (sales-side) or where you buy (purchasing-side). The answer changes nearly every position, like liability caps, who pays if something goes wrong and who owns the IP.
Employment legalYour role and setting, and every state and country where you have employees.
IP legalYour role, setting and jurisdiction, and which kinds of IP you work in: trademark, patent, copyright, trade secret or open source.
Product legalYour role, how formal your review is (a formal gate or advice only) and whether you sell to consumers, businesses or both.
The questions are written for lawyers. If an option doesn't fit a business owner, such as "practice setting", say so in your own words. The interview says it will build your profile from what you tell it.
Where you are matters. Much of the repo is written around US law. The hiring check flags a first hire in a new place as needing research, and the trademark check says when it has no framework for a country. Tell the interview where you operate, and check anything outside the US more closely.
Optional: connect a research tool. The README says citations are unverified without one, and flags them [verify]. The repo's quick start suggests CourtListener, a public database of US court opinions and dockets, added under Connectors. The plugins work without it, but every citation then needs a person to check it.
06First runs

What your first runs look like.

Each agent asks what it needs, does the work and hands you a draft. If you said you're not a lawyer, it stops before the step that matters and asks whether a lawyer has seen it.

  • 1The brand-name check

    Command: /ip-legal:clearance. It asks once for the exact name, what you sell under it, where you plan to use it and how it will appear.

    You give it a brand name and what it's for. You get back a memo that checks the name for built-in problems, like being generic or describing the product, looks for similar marks and lists the factors that decide whether people could confuse the two.

    Read the top line: it says this is "a first pass, not a clearance opinion". Without a trademark search tool connected, it says no database search was run and weighs only the marks you mention. Finding nothing doesn't mean the name is free to use. The agent's instructions say it never concludes a mark is clear.

  • 2The claims check

    Command: /product-legal:marketing-claims-review. Paste the copy.

    You give it a landing page, an email or an ad. You get back every claim sorted as a provable fact, a comparison, an implied claim, an absolute claim or plain puffery, with a call on each: fine, needs substantiation, needs rewording or cut. You also get a suggested rewrite that keeps the energy, and a list of the proof you need before it ships and who has it.

    It fixes the copy. It doesn't write your marketing, and it doesn't prove a claim for you.

  • 3The offer-letter check

    Command: /employment-legal:hiring-review. Say where the person will work, because that place's rules apply, not your head office's.

    You give it the offer letter, or a description of the hire. You get back an overall call (clear to send, changes needed or escalate) and a checklist of changes to make before you send it. It looks at how the job is classified (exempt or non-exempt, a US test), non-competes and similar clauses, pay-range rules and required notices. Outside the US it checks different things, like notice periods and the written terms the country requires.

    If you said you're not a lawyer, it won't mark the offer clear to send unless you confirm an attorney has reviewed it. If you haven't, it gives you a brief to take to one. It reviews the letter. It doesn't draft it or decide the hire.

  • 4The contract review

    Command: /commercial-legal:review. In Cowork, Anthropic's walkthrough puts the contract and your rules in one folder and adds it with + Add folder.

    You give it a vendor agreement, an NDA or a software subscription, as a file, a link or pasted text. You get back a memo that sets each clause against your rules from setup (your playbook). It lists the gaps, how risky each one is, suggested redline wording and who should approve. A redline is the contract with your proposed changes marked up.

    It reads the document's titles first, says what kind of agreement it thinks it has and waits for you to confirm. An inbound NDA gets a quick traffic-light triage. If you said you're not a lawyer, you get what it found and questions to ask before you sign, not a green light.

Look for the tags. Every citation in an output says where it came from. The README says citations from the model's own knowledge are flagged [verify]. Check those first, and check the rest too.
The README says the plugins have "explicit gates before anything is filed, sent, or relied on." Expect them to stop and ask.

07Runs on its own

The agents that run on a schedule.

Ten of the 93 agents are scheduled: they check something on a timetable and post what they find. The one from the Reel is the Renewal Watcher.

The agent's own file says it runs weekly, Monday morning, and that this is configurable. It reads your renewal register, a list of contracts with their cancel-by dates, and posts what is coming in the next 90 days. A cancel-by date within 13 days goes out straight away, marked red. Dates 14 to 44 days out are orange and 45 to 89 days are yellow. If nothing is due it posts a short all-clear, so you know it ran. It posts to the Slack channel or email list named in your practice profile.

It only knows the contracts in the register. It doesn't read your contracts itself. The register fills when you review a contract with /commercial-legal:review, which hands over any renewal it finds, or when you ask Claude to add one to the renewal tracker. If you use Ironclad or DocuSign, connect it and the tracker can load everything in one go. Contracts you signed before you installed the plugin need a one-time scan. So "it looks at all your contracts" is true once they are in the register. It never cancels or renews anything. It tells you when to decide.

Try it on demand first

This shows the same list when you ask for it, grouped by how soon each cancel-by date is:

/commercial-legal:renewal-tracker

If you said you're not a lawyer, it pauses before you accept or decline a renewal and asks whether an attorney has reviewed it.

Making it run by itself

The README says installed scheduled agents run on the cadence set in their files. The Renewal Watcher's file gives its cadence in words, not as a setting, so confirm the Monday run happens before you rely on it.

Anthropic's own scheduling is the documented way to run a task on a timetable. In Cowork, click Scheduled in the left sidebar or type /schedule, say what should run and how often, and approve the schedule Claude proposes. A scheduled task can use your installed plugins, so you can ask for the renewal list every Monday. Anthropic's help page says scheduled tasks run on their schedule even when your computer is asleep or the app is closed, but a task that needs files or apps on your computer only runs there. The register is a file on your computer, so expect your computer to need to be on.

08What to do now

Pick one. Do it today.

Seeing it run tells you more than reading about it. Start where you are.

  • If you just want to see it: add the marketplace in Claude Desktop (section 03), install Commercial legal and type / in a task. If its commands show up, it worked.
  • If you have a brand name in mind: install IP legal, do the quick setup and run /ip-legal:clearance on the name. Then take the memo to a trademark lawyer before you spend money on the name.
  • If you are about to hire: install Employment legal and run /employment-legal:hiring-review on the offer letter, with the place the person will work.
  • If a contract is waiting on you: install Commercial legal, do the quick setup and run /commercial-legal:review on it.
  • If copy is about to go live: install Product legal and run /product-legal:marketing-claims-review on it.
  • If you want the renewals list: put your contracts through the review once so the register fills up, then run /commercial-legal:renewal-tracker (section 07).
  • If a step doesn't match your screen: the repo and Anthropic's help pages are the source, and the menus move around. Start from the repo address in section 01.
