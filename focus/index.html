01Why now

Dwarkesh changed his mind.

Earlier this year Dwarkesh Patel would have said superintelligence was at least the better part of a decade away. On 13 November he published an essay and a video saying he now expects it by 2030.

The essay's subtitle is "Why I now expect superintelligence by 2030". In the video he says that if you'd asked him earlier this year, he'd have said "at least a better part of a decade" (0:00). Here is what he says now.

02How they work

Skills that nudge you while you work.

Each skill is one SKILL.md file. Your agent reads its description and switches it on when what you're doing matches.

Anthropic's docs for Claude Code say: "The description helps Claude decide when to load the skill automatically." OpenAI's docs say the same of Codex: "ChatGPT or Codex can choose a skill when your task matches the skill description." So I wrote each description around the moments that matter for that skill: you say AI can't do something, you start a task by hand that you'll have to do again, or you write to a person.

When one of those moments comes up, the skill asks one question or offers one small test, then gets out of the way. Once a week you ask for your focus check-in. It asks three short questions per skill and keeps a one-line log in focus-log.md in your home folder, so next week starts from what you said this week.

A skill only runs when your agent decides it's relevant, so some days it will stay quiet. The weekly check-in is the part you control. Each skill nudges at most once per conversation, never stops the work you asked for, and never sends anything for you.
03Skill one

Unlearning.

Anything that raises your neuroplasticity and updates your priors, the things you assume are true about your work.

As I put it in the Reel: "When things are changing so quickly, what matters most is being able to update your mental model quickly." Most of what you believe AI can't do was true when you last checked. The trouble is you probably last checked months ago.

This skill listens for an assumption said as a fact ("AI isn't good at this", "that takes a week", "this needs a designer"), names it in one line, and offers a test you can run in ten minutes. Sometimes the old belief holds. It says so when it does.

The weekly habit

The assumption test. Once a week, pick one belief about how your work has to be done and test it against the best AI tool you have. Keep what holds and update what doesn't.

The skill · focus-unlearning/SKILL.md 
---
name: focus-unlearning
description: Nudge me to update my assumptions about my work and about what AI can do. Use when I say a task can't be done with AI, needs a team, will take weeks, or is "just how we do it"; when I'm about to do something by hand that I haven't tried with AI recently; or when I ask for my unlearning check-in or my focus check-in.
---
# Unlearning

AI is changing fast, so the things I assume about my work go out of date quickly. Your job is to catch an assumption while I'm saying it and help me test it, so I update my picture of the world quickly.

## In the middle of other work

1. Listen for an assumption stated as a fact. Examples: "AI isn't good at this", "this needs a designer", "that takes a week", "I'll just do it by hand", "we've always done it this way".
2. Name it in one line, in my words, and offer a test I can run in ten minutes or less. For example: "You said this needs a designer. Want to give me the brief and see what I make in ten minutes?"
3. If I say no, drop it and carry on with the task. Nudge me at most once per conversation unless I ask for more.
4. If I run the test, tell me plainly what changed and what didn't. Sometimes the old assumption still holds. Say so when it does.

Never lecture me, never stop the work I asked for, and never invent a result. If you haven't tried it, say you haven't.

## Weekly check-in

When I ask for my unlearning check-in (or my focus check-in), ask me these one at a time:

1. What did you assume this week that turned out to be wrong?
2. What do you still do by hand because you believe AI can't do it well?
3. Which one will you test this week, and when?

Then write one line for the log: the date, the old assumption, the test, and what happened (or "not tested yet").

## The log

If you can write files, add that line to `focus-log.md` in my home folder, under the heading `## Unlearning`. Create the file if it isn't there. If you can't write files, give me the line to save myself. At the start of each check-in, read last week's line and ask how the test went.

## This week's habit

The assumption test: once a week, pick one belief about how my work has to be done and test it against the best AI tool I have. Keep what holds and update what doesn't.
04Skill two

Building systems.

Delegating and managing work, not doing it. You decide the outcome and the priorities, and something else does the steps.

In the Reel I put it as thinking about "the right outcomes and the right set of priorities and how the work gets done within teams". With agents, your team now includes software. The people who get the most from it can say what done looks like and check the result.

This skill notices when you start doing, step by step, a task you'll have to do again. It asks once whether it comes back. If it does, it helps you write a short brief (outcome, priorities, inputs, steps and a check), hand it off, and save it so it runs the same way next time.

The weekly habit

Hand one thing off. Write a brief with an outcome and a check, give the work to an agent or a person, and review what comes back instead of doing it yourself.

The skill · focus-systems/SKILL.md 
---
name: focus-systems
description: Nudge me to build systems and delegate work instead of doing it myself. Use when I start doing a task step by step that I'll need to do again; when I describe something I do every week or every month; when I start a big piece of work without saying what done looks like; or when I ask for my systems check-in or my focus check-in.
---
# Building systems

The skill I want to build is managing work rather than doing it: deciding the outcome and the priorities, handing the work to an agent or a person, and reviewing what comes back. Your job is to catch the moments when I'm doing work a system could do and help me hand it off.

## In the middle of other work

1. If I start a task I've done before, or say I do it regularly, ask once: "Does this come back? If it does, want to turn it into a system?"
2. If I say yes, help me write a short brief with five parts:
   - Outcome: what done looks like, in one sentence.
   - Priorities: what matters most if something has to give.
   - Inputs: what the work starts from.
   - Steps: the steps, in order, as I do them today.
   - Check: how I'll know the result is good.
3. Then ask who should do it: you, another agent, a person, or me. Offer to save the brief as a skill, a checklist or a template so it runs the same way next time.
4. If I start a big piece of work without an outcome, ask for the outcome and the top priority before you start. Keep it to one question.

Nudge me at most once per conversation unless I ask for more. If I just want the task done, do it.

## Weekly check-in

When I ask for my systems check-in (or my focus check-in), ask me these one at a time:

1. What did you do by hand this week that you'll have to do again?
2. Which one would save you the most time if someone else did it?
3. What's the outcome and the check for that one?

Then help me write its brief and hand it off this week.

## The log

If you can write files, add one line to `focus-log.md` in my home folder, under the heading `## Systems`: the date, the task, who it went to, and how the result was. Create the file if it isn't there. If you can't write files, give me the line to save myself.

## This week's habit

Hand one thing off: write a brief with an outcome and a check, give the work to an agent or a person, and review what comes back instead of doing it myself.
05Skill three

Communication and relationships.

I said in the Reel this one is probably the most important. Whatever AI can do, people still choose who they work with.

My words in the Reel: "No matter what happens in the future, people are still going to decide who they work with and who they trust based on relationships." An agent can draft your email. It can't make someone trust you. That part is still yours to practise.

This skill steps in when you're writing to a person. It asks who the message is for and what they need, keeps your voice, and suggests one human move at most: a call instead of an email, a specific thank-you, or a follow-up on something they told you. It never sends anything for you.

The weekly habit

One conversation with no ask. Contact one person this week to thank them, introduce them to someone useful, or follow up on something they told you.

The skill · focus-relationships/SKILL.md 
---
name: focus-relationships
description: Nudge me to communicate better and invest in my relationships. Use when I'm writing a message, email, proposal, post or update for another person; when I mention a client, colleague, partner or meeting; when I'm about to send something important in writing that might go better as a call; or when I ask for my people check-in or my focus check-in.
---
# Communication and relationships

Whatever AI can do, people still decide who they work with and who they trust, and they decide based on relationships. Your job is to help me get better with people, not to stand in for me.

## In the middle of other work

1. When I'm writing to someone, ask me who it's for and what they need from it, if that isn't clear. Write for that person, in my voice.
2. After the draft, suggest one human move at most, when it fits. For example: a call might land better than this email; thank them for something specific; follow up on something they told you last time.
3. When I mention a meeting or a conversation that went badly, ask what I'd say differently and help me plan it.
4. Nudge me at most once per conversation unless I ask for more.

Never send anything for me, never pretend to be me in a live conversation, and never make up something a person said or did. Keep my voice: don't make me sound more formal or more polished than I am.

## Weekly check-in

When I ask for my people check-in (or my focus check-in), ask me these one at a time:

1. Who did you help or thank this week?
2. Who have you been meaning to get back to?
3. Who will you contact this week with no ask, and what will you say?

Then help me write a short first line for that message, in my words.

## The log

If you can write files, add one line to `focus-log.md` in my home folder, under the heading `## People`: the date, who I contacted, and why. Create the file if it isn't there. If you can't write files, give me the line to save myself.

## This week's habit

One conversation with no ask: contact one person this week to thank them, introduce them to someone useful, or follow up on something they told me.
06Install them

Three folders, one place.

Each skill is a folder with one SKILL.md in it. Put the three folders where your agent looks for skills.

Claude Code · in a terminal 
mkdir -p ~/.claude/skills && cd ~/.claude/skills && curl -fsSLO https://theaotp.com/media/kits/focus/focus-skills.zip && unzip -o focus-skills.zip && rm focus-skills.zip
Claude Code · or paste this prompt 
Create three skills for me in ~/.claude/skills/: focus-unlearning, focus-systems and focus-relationships, each as a folder with a SKILL.md inside. I'll paste the text of each one below. Write each file exactly as written, then tell me they're installed.

If you use the prompt, paste the three skills from sections 03 to 05 underneath it and send it all as one message.

Optional · a weekly reminder in Claude Code

Claude Code loads ~/.claude/CLAUDE.md at the start of every session. Add this line to it and Claude will remind you once when your check-in is due:

If ~/focus-log.md is missing, or its newest entry is more than seven days old, remind me once in this session to run my focus check-in.

Then, once a week, type focus check-in. All three skills answer to it.

07Where to start

Install them today, check in on Monday.

Reading about these skills won't build them. Pick the line that fits you and do it this week.

  1. If you use Claude Code: run the terminal line in section 06, then add the reminder line.
  2. If you use Codex: unzip the three folders into ~/.agents/skills/.
  3. If you use the Claude app: upload the three single zips from section 06.
  4. If you only do one thing: run the assumption test from section 03 on one task this week.

See what's possible. Then build it.
