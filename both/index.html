The Both Kit · From the Reel

Run Claude and Codex in the same project.

You commented "both". Here it is: the install steps with screenshots, how to run both CLIs side by side in VS Code, then three prompts that build the file system both models read. Instruction files, a shared skills folder, and a wiki that holds your context. No course, no upsell.

00 · The shape of it

One folder. Two models. Any terminal.

The chat apps make you pick a model. VS Code with both CLIs in its terminal does not. You open a terminal, type claude or codex, and both read the same files.

This is the setup from the video. Part one installs the tools. Part two is the prompts that build the folder so it works with either model. Do it in order, it takes about an hour the first time.

  1. 01Install VS Code and open a terminal
  2. 02Install Claude Code
  3. 03Install the Codex CLI
  4. 04Run them side by side
  5. 05Prompt 1: CLAUDE.md and AGENTS.md
  6. 06Prompt 2: one skills folder, both agents
  7. 07Prompt 3: the wiki that holds your context
  8. 08Cross model review
Costs: Claude Code needs a Claude Pro or Max plan. Codex needs a ChatGPT Plus or Pro plan. Two subscriptions, two separate quotas, no API keys. The "am I in the loop" rule: subscriptions for the work you sit at, per token APIs only for things that run without you.
01 · Install

VS Code, then a terminal inside it.

VS Code is the room both models work in. The file explorer on the left is your project, the terminal at the bottom is where you talk to them.

Download it from code.visualstudio.com/download. On a Mac pick "Apple silicon" unless your machine is an older Intel one. Open the app, then:

  1. File → Open Folder and choose the folder you want as your workspace. Make a new empty one if you are starting fresh. Every file both models read will live in here.
  2. Terminal → New Terminal (or ctrl + `). A panel opens at the bottom, already sitting in your folder.
02 · Install

Claude Code in the terminal.

One line in the VS Code terminal. It installs a native binary and keeps itself updated.

curl -fsSL https://claude.ai/install.sh | bash

Homebrew works too (brew install --cask claude-code), and so does npm if you already have Node 22 or later (npm install -g @anthropic-ai/claude-code). Any one of the three. Then check it took, and start it:

~/my-project $ claude --version 2.1.263 (Claude Code) ~/my-project $ claude

The first run opens your browser to log in with your Claude account. After that you are in a chat inside the terminal that can read and edit the files in your folder. Type /model to pick the model and the effort level. I run Fable 5.1 on medium for most work.

Do not run the npm install with sudo. If the terminal says "command not found" after installing, close the terminal panel and open a new one so it picks up the new path.
03 · Install

The Codex CLI next to it.

Same idea, OpenAI's side. One line, then sign in with your ChatGPT account.

curl -fsSL https://chatgpt.com/codex/install.sh | sh

Or npm install -g @openai/codex if you prefer npm. Check it, start it:

~/my-project $ codex --version codex-cli 0.153.4 ~/my-project $ codex

Pick Sign in with ChatGPT on the first run. Inside Codex, /model lets you choose the model and reasoning effort. I run GPT Astra on high. That choice is saved in a config file so you do not repeat it.

If you want the defaults written down rather than picked each time, put this in a file called .codex/config.toml inside your project folder:

model = "gpt-6-astra" model_reasoning_effort = "high" approval_policy = "on-request" sandbox_mode = "workspace-write"
04 · Run

Two terminals, one on each model.

This is the whole trick from the video. Each terminal tab is a separate agent working on the same folder. You add one by opening another terminal and typing the other command.

  1. In the terminal panel click the + (or press ctrl + shift + `). A second terminal opens. The list on the right of the panel shows every open terminal.
  2. In terminal 1 type claude. In terminal 2 type codex.
  3. Right click a terminal in that list and Rename it after what it is doing. When you have four running this is what stops you sending the wrong instruction to the wrong agent.
  4. Want them visible at the same time? Click the split icon next to the + and they sit side by side.
Terminal 1 Claude Code v2.1.263 Fable 5.1 with medium effort · Claude Max ~/my-project Terminal 2 OpenAI Codex (v0.153.4) model: gpt-6-astra high directory: ~/my-project
Both models are editing the same files. Give them different jobs at the same time (one reviews the website while the other updates docs), or the same job in sequence (one writes, the other reviews). Do not give two agents the same file at once.
05 · Prompt 1

CLAUDE.md and AGENTS.md: the two files both agents read first.

Claude Code reads CLAUDE.md on its own. Codex reads AGENTS.md. Instead of writing the same instructions twice, one file is the source of truth and the other is a short adapter that points at it.

Start claude in your folder (Codex works too) and paste this. It interviews you first, then builds the files from your answers.

You are setting up the instruction files for my personal AI workspace. This folder will be
used by Claude Code and the Codex CLI on the same project at the same time, so both agents
need to read the same rules from the same place.

Before you write anything, interview me. Ask these five questions in one numbered message and
wait for my answers:

1. What do you do, and what should an AI agent know about your role?
2. What are the two or three projects or areas you will work on in this folder?
3. What tools and platforms do you live in day to day?
4. How do you like things written? Tone, length, formatting rules, anything you hate.
5. What are the hard rules? Folders that must never be touched, secrets, things to always ask
   before doing.

When I have answered, create exactly two files:

1. `CLAUDE.md` at the root. The single canonical instruction file for the whole workspace.
   Sections, in this order: who I am and how I work; a map of every folder and what belongs
   in it (create the map even if the folders do not exist yet, we build them next); my writing
   rules; my hard rules; and a final section titled "Source of truth" containing this sentence
   word for word: "CLAUDE.md is the canonical instruction file. AGENTS.md is a thin adapter for
   Codex and never duplicates this file. If they ever disagree, CLAUDE.md wins."

2. `AGENTS.md` at the root. The Codex adapter, 25 lines or fewer. It must: tell Codex to read
   `CLAUDE.md` in full and treat it as canonical; say that skills live in `.claude/skills/` and
   are shared, never copied; say that any durable change gets written into the canonical owner,
   not into this file; and list anything Codex specifically needs to know (for example that it
   does not auto load nested CLAUDE.md files, so it must look for the nearest one before working
   in a subfolder).

Rules: do not restate CLAUDE.md content inside AGENTS.md. Keep both files in plain Markdown.
Do not invent facts about me that I did not give you.

When done, print both files in full, then confirm two checks: AGENTS.md is 25 lines or fewer,
and AGENTS.md contains the phrase "Read `CLAUDE.md` in full".
06 · Prompt 2

One skills folder both agents can find.

A skill is a folder with a SKILL.md that says when to use it and exactly how to do the job. Claude Code looks in .claude/skills. Codex looks in .agents/skills. A symlink makes them the same folder, so you write a skill once.

Run this after Prompt 1. It builds the folder, the link, a check script, and your first real skill from something you already do on repeat.

Set up a shared skills tree for this workspace so Claude Code and the Codex CLI use the exact
same skills.

Do this:

1. Create `.claude/skills/` as the canonical skill tree. Add `.claude/skills/README.md`
   explaining the format: each skill is a folder named in kebab-case containing a `SKILL.md`
   with YAML frontmatter (`name`, and a `description` written as the trigger phrases a person
   would actually say) followed by the step by step procedure.

2. Create `.agents/skills` as a symlink to `../.claude/skills` so Codex discovers the same
   tree. If this system cannot make symlinks, stop and tell me instead of copying files.

3. Write `bin/check-agent-adapters.sh`, a small bash script that fails loudly if:
   the symlink is missing or points somewhere else; `CLAUDE.md` is missing; `AGENTS.md` is
   missing or no longer contains "Read `CLAUDE.md` in full"; or any `SKILL.md` links to a
   supporting file that does not exist. Print PASS or FAIL per check. Run it and show me the
   output.

4. Interview me for my first skill. Ask: "What is one job you do at least weekly that has the
   same steps every time? Walk me through the steps as you would tell a new hire." Wait for my
   answer, then write `.claude/skills/<name>/SKILL.md` from it. The description must be the
   phrases I would say to trigger it. The body must be a procedure another agent can follow
   without me present, including what "done" looks like and what to do when a step fails.

5. Add a line to `CLAUDE.md` under the folder map: `.claude/skills/` is the canonical skill
   tree, mirrored to `.agents/skills` for Codex, and any skill change is made in the canonical
   tree only.

Finish by running the check script again and showing that every check passes, then print the
new SKILL.md in full.
Test it from the other side: open a Codex terminal and ask it to list the skills it can see. If it names the one you just wrote, the link works.
07 · Prompt 3

The wiki: everything about you, in one place.

Instructions tell an agent how to behave. Context tells it what is true. The wiki is the folder where the context lives, so "know everything about me and this project" is a set of files, not a hope.

This one interviews you longer. Answer in rough notes, it does the writing.

Build the context wiki for this workspace: a folder of Markdown files that holds everything an
AI agent should know about me and my work, readable by both Claude Code and the Codex CLI.

First, interview me. Ask these in one message, numbered, and wait:

1. Background: what I do, how long, what I am known for, what I am trying to become known for.
2. Projects: every active project, its goal, its current state, and what done looks like.
3. People: the people and organisations I work with most, and what each one needs from me.
4. Decisions: three to five decisions I have already made that an agent must not reopen (tools
   I have chosen, things I have ruled out, standards I hold to).
5. Sources: the documents, links, and accounts I go back to all the time.
6. Tools: what I use, what I pay for, and what each one is for.

Then create `wiki/` with this structure and fill it from my answers:

  wiki/index.md          one line per file below, what it is for, when to read it
  wiki/about-me.md       who I am, how I work, how I like to be spoken to
  wiki/projects/         one file per project: goal, state, next step, done looks like
  wiki/people/           one file per person or organisation
  wiki/decisions.md      the standing decisions, each with the date and the reason
  wiki/sources.md        the links and documents I return to, with one line on why each matters
  wiki/tools.md          what I use and what each tool is for
  wiki/concepts/         empty for now, with a README saying it holds explanations of ideas I
                         keep having to re-explain
  wiki/summaries/        empty for now, with a README saying it holds digests of long documents
  wiki/log.md            a dated running log; today's entry says the wiki was created

Rules: only write what I told you, mark gaps as "TBC" rather than guessing; short files, one
topic each; every file starts with a one line summary so an agent can skim.

Then wire it in. Add to `CLAUDE.md`: "Before any task about me, my projects, or my people,
read `wiki/index.md` and the files it points to. After any task that changes what is true
(a decision, a project state, a new person), update the matching wiki file and add a line to
`wiki/log.md`." Add the same two sentences to `AGENTS.md` in one line pointing at that
section of CLAUDE.md.

Finish by printing `wiki/index.md` and the folder tree.
The second sentence you wired in is the one that matters. A wiki nobody updates is dead in a month. Making the agent responsible for updating it after each task is what keeps it alive.
08 · Use it

Cross model review: the part that pays for both plans.

One model writes, the other model reviews. They have different blind spots and no loyalty to their own work. It improves output quality more than any prompt I have found.

Simplest form, from the Claude terminal, after Claude has made a change:

codex exec review

Codex reads the diff and reviews it as a second pair of eyes. The reverse works too: have Codex build something, then ask Claude in the other terminal to "review the diff Codex just made, be adversarial, run the tests". Two more commands worth knowing:

CommandWhat it does
codex exec -s workspace-write "<task>"Hand a task to Codex without opening the chat. It can write files in the project, nothing outside it.
codex exec resume --last "<feedback>"Send feedback back into that same Codex session so it fixes its own work with full memory of what it did.
codex -m gpt-6-astra -c model_reasoning_effort=lowStart Codex on a specific model and effort for one session. Low for mechanical work saves your quota.

The handoff that works: write the task as a file the other model can read on its own (it cannot see your chat), let it build, then review the actual diff yourself or with the other model. Never trust a model's summary of its own work.

09 · What to do now

Pick one. Do it today.

Reading this changes nothing. Having both terminals open on a real project does.

  • If you have neither CLI yet: steps 01 to 04. Stop when you have two terminals running. Come back tomorrow for the prompts.
  • If you already use one of them: install the other (02 or 03), then run Prompt 1 so the newcomer reads the same rules.
  • If you have both and a folder already: skip to Prompt 3. The wiki is the piece most people never build, and it is the piece that makes the agents feel like they know you.
  • If it all works: pick the next thing you build and run codex exec review on it before you ship. That habit is the whole point.

See what's possible. Then build it.
