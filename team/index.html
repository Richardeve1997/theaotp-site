01 What it is

Four things that turn agents into a team.

Claude, Codex or another agent does the work. Paperclip gives each one a job, a manager, skills and a budget, and tracks the work and the cost on one dashboard.

You run it on your own machine, and you don't need a Paperclip account. It's open source under the MIT license, with over 95,000 stars on GitHub when I checked today. In the Reel I called it a free version of Grok Bot that works with any AI model. Grok Bot keeps your team on Grok's models. Paperclip lets you choose the model for each agent, and each agent can run a different one.

Here are the four things from the Reel, under the names Paperclip's README uses, and the step where you set each one up:

02 Install

One command. Then open your browser.

Paperclip runs on your own computer, and once Node.js is on it, the install is a single command.

You need Node.js 24.11 or newer. Check what you have:

node --version

If it prints something older, or nothing, get the LTS installer from nodejs.org. Then run the quickstart from Paperclip's README:

npx paperclipai@latest onboard --yes

That command downloads Paperclip, writes its config, sets up a built-in database and starts the server at http://localhost:3100. Paperclip opens in your browser. If it doesn't, go to that address yourself.

Run it as your normal user, never with sudo. The built-in database refuses to start under an admin account.

Starting it again later

That command holds your terminal open, and closing the window stops Paperclip. After you restart your computer, bring it back with:

npx paperclipai run

Once you're using it every day, these two commands from the install guide turn it into a background service that starts when you log in:

npx paperclipai install
paperclipai service install

The first one offers to add paperclipai to your PATH. Say yes, then open a new terminal window before you run the second.

On an Apple Silicon Mac, if onboarding fails while the built-in database starts, the install guide has a short symlink fix. That guide also adds a pnpm step the README's quickstart doesn't list. I'd skip it unless onboarding asks for pnpm. Paperclip also sends anonymous usage telemetry by default. Set DO_NOT_TRACK=1 or PAPERCLIP_TELEMETRY_DISABLED=1 to turn it off.
03 Connect a model

Your model. The plan you already pay for.

Every agent runs through an adapter, and the adapter decides which AI does the work. That's the operating system from the Reel.

Paperclip doesn't ship with a model. It drives an agent CLI that lives on the same machine, and the two adapters its docs mark as recommended are Claude Code and Codex. Install the one you want and sign in before you create your first agent, because the setup wizard asks for it.

Claude Code

curl -fsSL https://claude.ai/install.sh | bash

Then run claude and follow the browser prompts to log in. Claude Code needs a Pro, Max, Team, Enterprise or Console account. The free claude.ai plan doesn't include it. Other ways to install: Claude Code setup.

Codex

npm install -g @openai/codex

Then run codex and choose Sign in with ChatGPT. That puts it on your Plus, Pro, Business, Edu or Enterprise plan. Other ways to install: the Codex README.

Subscription or API key

This is how you bring the subscription you already have. Paperclip's Codex adapter links the Codex login already on your machine into each agent, so a ChatGPT plan carries over with no extra setup. The Claude Code adapter accepts a Claude subscription login or an ANTHROPIC_API_KEY. If you'd rather pay per use, the getting-started guide has you create an API key at console.anthropic.com or platform.openai.com and add it to the agent as an environment variable. On Codex, a key set on the agent wins over the login.

Any other model

Pick a different adapter. These ship with Paperclip too:

Before you save an agent, press Test environment. It checks the CLI is installed, the working folder is usable and the login works, then sends a one-line hello prompt. Paperclip's guide also suggests your most capable model for the CEO and a faster, cheaper one for workers doing routine tasks. 04 Your company

Name it, hire a CEO, set a goal.

The first time Paperclip opens, a setup wizard takes you through three screens: name your organization, hire your first agent, connect a model.

  • 1Name it.The first screen asks "What is the name of your organization?" Type a name and click Continue. The app says organization where the docs say company. They mean the same thing.
  • 2Hire the CEO.Your first agent is always the CEO. It reads your goal, proposes a strategy, creates tasks and hands them out. Pick the adapter you set up in step 03, a working folder and a model, then press Test environment. No folder in mind? The docs suggest making one called paperclip-workspace on your Desktop.
  • 3Set the goal.The wizard doesn't ask for one. Add it afterwards in the Goals section. Every agent can see it, so give it a measurable outcome and a deadline.
  • 4Set a budget.Open the CEO's Budget tab and set a monthly cap. The docs suggest $30 to $50 a month for a CEO to start. The company has its own budget too, and if either one runs out, the agent pauses.

Here's the shape I'd use for the goal. The example is straight from Paperclip's guide:

[A specific outcome] by [a date], measured by [one number].

Example: Publish 4 high-quality blog posts per week and grow organic traffic to 10,000 monthly visitors by June
Agents make real API calls. Paperclip's quickstart says to plan on $5 to $20 to try it out and $20 to $100 a month for an active company, and to set budgets before you switch heartbeats on. Paperclip pauses an agent automatically at 100% of its budget. That money goes to your model provider, not to Paperclip. Docs for this step: Create Your First Company, Hire Your First Agent and Costs.
05 The org chart

Give every agent a boss and a job.

Each agent gets a title and a manager, and the CEO uses that tree to decide who gets which work. This is the org chart from the Reel.

Every agent except the CEO reports to exactly one manager, and the CEO reports to you. Work gets delegated down the tree. Blockers escalate back up. A team that has grown past the CEO looks like this:

CEO ├── CTO │ ├── Backend Engineer │ └── Frontend Engineer └── CMO └── Content Writer
  • 1Add an agent.Go to Agents and click New Agent.
  • 2Give it a role.Add a name, a title such as CTO or CMO, and the closest role. The role tells the CEO what this agent is for.
  • 3Set its manager.In Reports to, managers get the CEO and workers get their manager.
  • 4Pick its model.Choose the adapter and model, click Create agent, then set its cap on the Budget tab.

Click Org in the sidebar to see the whole team as a tree, with each agent's status and adapter on its card. The docs' advice is to start small: see what work the CEO creates, then hire as gaps show up.

Or install a ready-made team

The Team Catalog page has starter teams you can preview, then install in one go. The core executive team gives you a CEO, a CTO and a QA agent, plus a starter project and a recurring CEO heartbeat task. You pick the runtime for each agent as you install, so a Claude or Codex login from step 03 works here too. Already have agents? Attach the new team under an existing manager and it joins your org chart.

Docs for this step: Org Structure and Team Catalog.
06 Training

Teach them skills. Then test them.

The training area from the Reel is where you assign skills to each agent and test them before they touch real work.

A skill is a folder with a SKILL.md file inside, the written steps for one procedure, like a code review checklist or a customer reply template. Each agent sees the description of every skill it has at the start of a run, and loads the full instructions only when the task needs them.

  • 1Fill the library.Open Skills in the sidebar. Paste a GitHub URL or a skills.sh install command into the source field and press Add, install one from the built-in catalog, or press + to write your own.
  • 2Assign them.Open an agent, go to its Skills tab and tick the skills it should use. It saves on its own, and the agent picks them up on its next run.
  • 3Test them.Open Skill Studio from any skill in your library. Paste an input or pick a saved one, choose an agent, press Run and read what comes back. Test runs happen on a hidden task, so they stay out of your real issue list.
Every save in Skill Studio creates a new version of the skill, and Version history lets you restore an earlier one. So if an edit makes an agent worse, you can roll it back. Docs for this step: Skills.
07 The task manager

Set a task. Watch it work. Review it.

The task manager is where you'll spend most of your time: you hand out work, watch it happen and sign it off.

Switch the CEO on

  • 1Turn on the heartbeat.A new agent starts with its heartbeat off. Open the CEO from Agents and flip the heartbeat toggle. To start it right away, click Run Heartbeat.
  • 2Approve the strategy.After its first run, the CEO usually sends you a Strategy approval. Open Approvals, read it, then choose Approve, Request revision or Reject. The CEO can't create tasks until you approve.
  • 3Watch the board fill.Its tasks land on the Issues page as todo or backlog. With only a CEO, it assigns them to itself. Hire more agents and it starts handing work out by role.

Give it a job yourself

Click New Issue. Start the title with a verb and name the outcome. Pick a work mode: Agent mode does the work, Plan mode writes a plan for you to review first, and Ask mode just answers in the thread. Then set a priority and an assignee. Assigning an issue wakes that agent straight away by default.

The description is the brief the agent works from. Paperclip's guide says to cover what you want, the constraints, what done looks like and any references. Here's the brief I'd start from:

What I want: [the deliverable, and the standard it needs to meet]
Constraints: [length, tone, budget, what not to change]
Done looks like: [how we'll both know it's finished]
References: [links, files or examples to work from]

Watch it run and review it

An issue with an agent working on it shows a live-run indicator. Open it and read the comments: agents post what they did, what they found and where they're stuck. Reply in the thread to steer. If the agent has wake on mention switched on, an @mention like @CEO wakes it.

When the work is finished, the issue moves to done, or to In Review if you've set up a review step. Not happy? Comment and the agent picks it back up. For the full record of any run, open the agent and click Runs: the transcript shows every step it took and every tool it called.

Docs for this step: Watching Agents Work and Issues.
08 What to do now

Pick one. Use it today.

Reading this won't run your team. Putting one real task through it this week will.

  • If you've never opened a terminal: start at step 02. Once Node.js is installed, it's one command.
  • If you already use Claude Code or Codex: step 03 is mostly done. Check you're signed in, then go to step 04 and hire your CEO on that login.
  • If you want a full team today: install the core executive team from the Team Catalog in step 05.
  • If you already have agents running: go to step 06 and test one skill in Skill Studio before you trust it with real work.
  • If you're worried about spend: set the budgets in step 04 before you flip the heartbeat in step 07.
